# Build a Complete, Working, Demo-Ready Gmail Spam Detection ML Web Application

Build a complete, production-style, demo-ready ML web application that connects to a real Gmail inbox using the official Gmail API and Google OAuth 2.0, fetches recent inbox emails, and classifies them as `Spam` or `Not Spam` using a genuinely trained `TF-IDF + Multinomial Naive Bayes` model.

This must be a REAL end-to-end application.

Do NOT create:

* Fake Gmail data
* Mock OAuth
* Fake API responses
* Hardcoded predictions
* Dummy confidence values
* Simulated inbox messages
* TODO comments
* Placeholder functions
* "Coming soon" features

Every core feature must actually work.

---

# 1. PROJECT GOAL

Create a web application called:

`Gmail Spam Detector`

The application should allow a user to:

1. Open the web application.
2. Understand what Gmail permission is required.
3. Click `Connect Gmail`.
4. Authenticate using a real Google account through OAuth 2.0.
5. Grant ONLY Gmail read-only permission.
6. Fetch recent real inbox emails using the Gmail API.
7. Extract sender, subject, snippet and readable body text.
8. Run every email through the trained spam detection model.
9. Display:

   * Sender
   * Subject
   * Email snippet/body preview
   * Spam / Not Spam prediction
   * Confidence percentage
10. Manually paste any message and classify it using the same trained model.

The final application should be suitable for a college faculty demonstration.

* `ham`

Normalize labels internally to:

`Spam`
`Not Spam`

## Text preprocessing

Implement a reusable preprocessing function.

Steps:

1. Convert text to lowercase.
2. Handle null/empty values safely.
3. Remove punctuation.
4. Remove unnecessary special characters.
5. Normalize whitespace.
6. Remove English stopwords using NLTK.
7. If NLTK stopwords are unavailable, gracefully fall back to a built-in stopword set instead of crashing.
8. Return cleaned text.

Do not over-clean text to the point that important spam indicators disappear.

## Training

Use:

* 80/20 stratified train-test split
* `random_state=42`
* `TfidfVectorizer`
* `MultinomialNB`

Example pipeline:

`raw text → preprocessing → TF-IDF → MultinomialNB`

The model must be trained ONLY by `train_model.py`.

Save:

`model.pkl`

and

`vectorizer.pkl`

Flask must load these files when the application starts.

NEVER retrain the model during every request.

## Evaluation

After training, print:

* Accuracy
* Precision
* Recall
* F1 Score
* Confusion Matrix

Use appropriate binary classification metrics.

Also print the number of training and testing samples.

Example console output:

`Model Training Complete`
`Accuracy: XX.XX%`
`Precision: XX.XX%`
`Recall: XX.XX%`
`F1 Score: XX.XX%`
`Confusion Matrix: ...`

Do not hardcode these values.

# 7. EMAIL BODY PARSING

This part must be implemented properly.

Gmail messages can be:

* Plain text
* HTML
* Multipart
* Nested multipart
* Base64url encoded

Create a robust email body extraction function.

Requirements:

1. Decode Gmail's base64url body encoding.
2. Recursively inspect multipart payloads.
3. Prefer `text/plain`.
4. If only `text/html` exists, convert HTML to readable plain text.
5. Remove unnecessary HTML markup.
6. Handle malformed/empty payloads safely.
7. Never crash because one email has an unusual MIME structure.

Do not display raw base64 or raw HTML to the user.

The text sent to the ML model should be readable email text.
